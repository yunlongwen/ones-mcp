# 快速配置指南 ⚡

> 📌 本项目采用**多用户认证模式**，服务端只需配置 2 个字段，用户认证信息由客户端提供

## 🎯 两步完成配置

### 第一步：服务端部署（运维人员做一次）

```bash
# 1. 进入项目目录
cd ~/mcp-server

# 2. 配置服务端（仅需 2 个字段）
cp config.example.json config.json
nano config.json

# 编辑内容：
{
  "ones_api_url": "http://172.16.81.11:30011/project/api",
  "team_uuid": "y7bXyZLk"
}

# 3. 一键部署
bash deploy.sh
```

> ✅ **服务端配置仅需 2 个字段**：API 地址和团队 UUID  
> ❌ **不需要配置**：用户邮箱、密码等认证信息

---

### 第二步：客户端配置（每个用户独立配置）

编辑 Cursor 的 `~/.cursor/mcp.json`（Windows: `%APPDATA%\Cursor\mcp.json`）：

```json
{
  "mcpServers": {
    "ones-wiki": {
      "url": "http://127.0.0.1:8000/sse",
      "description": "ONES Wiki知识库",
      "headers": {
        "x-user-email": "your_email@company.com",
        "x-user-password": "your_password",
        "x-default-space-uuid": "PLWdQVb5",
        "x-accessible-spaces": "C7ReCVYN,PLWdQVb5,Vj2fPcS7"
      }
    }
  }
}
```

**配置说明**：
- `url`: 服务器地址（询问运维人员）
- `x-user-email`: **你自己的** ONES 邮箱
- `x-user-password`: **你自己的** ONES 密码
- `x-default-space-uuid`: 你常用的空间 UUID（可选）
- `x-accessible-spaces`: 你能访问的所有空间（逗号分隔，可选）

> ⚠️ **重要**：每个用户使用自己的账号密码，不要共享！

## 🔍 如何获取配置参数

### 获取服务器地址

问运维人员要服务器 IP，格式：`http://<IP>:8000/sse`

### 获取空间 UUID

1. 打开 ONES Wiki 任意页面
2. 看浏览器地址栏
3. 格式：`http://xxx/wiki/#/team/y7bXyZLk/space/PLWdQVb5/page/xxx`
4. 复制 `PLWdQVb5` 这部分（空间 UUID）

### 获取多个空间 UUID

如果你能访问多个空间，把它们都列出来（逗号分隔）：

```json
"x-accessible-spaces": "space1,space2,space3"
```

## 🎉 多用户认证模式的优势

- ✅ **服务端简单**：只需配置 2 个字段（API 地址和团队 UUID）
- ✅ **集中部署**：只需要一台服务器，所有用户共享
- ✅ **用户独立**：每个用户使用自己的 ONES 账号
- ✅ **权限隔离**：基于 ONES 系统的权限控制
- ✅ **安全审计**：所有操作可追溯到具体用户
- ✅ **无需安装**：用户不需要安装 Python 或其他依赖

## 🛠️ 常见问题

### Q: 为什么不需要 `client_config_example.json`？

A: 因为现在直接在 `mcp.json` 中配置，不需要单独的配置文件。

### Q: 服务端的 `config.json` 需要配置用户信息吗？

A: **不需要！** 只需要配置 ONES API 地址和团队 UUID。用户信息通过 HTTP Headers 传递。

### Q: 多个用户可以用同一个服务器吗？

A: **可以！** 这正是 HTTP/SSE 模式的优势。每个用户在自己的 `mcp.json` 中配置自己的凭据。

### Q: 如何更新密码？

A: 直接修改 `mcp.json` 中的 `x-user-password`，然后重启 Cursor。
